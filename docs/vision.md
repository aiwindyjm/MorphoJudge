# 项目愿景

状态：愿景与边界草案，待讨论；不代表已实现能力。

## 起点

AI Coding 让需求到代码的距离缩短，但开发者仍需对软件行为负责。MorphoJudge（闪蝶判官）希望成为 AI 时代的软件可信判断层，帮助开发者理解、验证和控制 AI 生成或修改的软件。

## 服务对象

| 参与者 | 需要解决的问题 |
| --- | --- |
| 重度 AI Coding 开发者 | 快速理解一次变更，并定位必须亲自检查的代码 |
| 团队维护者与架构师 | 确认变更影响、设计约束与依赖边界 |
| 安全研究人员 | 复核行为证据，研究误报、漏报和绕过场景 |
| 企业内部开发团队 | 在代码不离开受控环境的条件下建立审查依据 |

## 核心原则

1. 本地优先：默认分析与推理留在本地或明确配置的内部环境。
2. 证据优先：判断应指向可定位的代码、Diff、规则或依赖记录。
3. 不确定性可见：区分提取事实、规则提示、模型推测与人工确认。
4. 人保留决策权：报告帮助审查，不自动批准生产发布。
5. 小步验证：先建立单个仓库、单一主要语言的最小闭环。
6. 开放协作：公开问题和设计边界，用可复核案例推动改进。

## 不以什么为目标

v0.1 不建设巨大平台，不替代 AI Coding Agent，不做自动修复或自动部署，也不以 IDE 插件作为核心交付物。不承诺证明任意软件安全，不把模型解释包装成合规认证。

代码扫描、结构分析和模型解释是实现目标的手段；项目价值在于把这些信息组织成开发者能验证的判断依据。

## 长期方向

探索跨语言关系分析、可复用行为规则、本地模型适配与可信判断的评测方式。知识图谱与企业集成是研究方向，不作为 v0.1 前置依赖。

## 如何知道项目有用

后续通过公开、可复现的评测观察：审查任务完成时间、事实准确率、误报与漏报、证据定位有效性、未覆盖项呈现情况，以及不同硬件下的资源成本。暂不设没有基线支撑的数字目标。
