# AI 协作与私有对话账本

状态：项目级操作规则，和根目录 `AGENTS.md` 配套使用。

## 规则文件层级

`AGENTS.md` 是唯一权威规则；`CLAUDE.md`、`GEMINI.md` 和 `.cursor/rules/morphojudge.mdc` 只是不同 AI 工具的兼容入口。更深层规则只能针对目录补充或收紧要求。该结构借鉴本地项目规则的共同实践，也符合 OpenAI 官方文档对 `AGENTS.md` 等项目指令文件会影响模型行为的说明。

## 会话生命周期

```text
启动 → 读 AGENTS.md 与适用规则 → 检查 Git、文档、当天账本
→ 公开说明目标/范围/标准 → 执行最小范围工作 → 验证并检查 diff
→ 追加当天私有账本 → 汇报完成、限制、阻塞和下一步
```

## 账本位置与命名

账本统一放在 `PRIVATE/conversations/YYYY-MM-DD.md`。同一天只使用一个文件，不按消息、工具或 Agent 拆成多个文件。`PRIVATE/`、`PRIVATE/conversations/` 和文件内容不会提交 Git；根目录 `.gitignore` 已覆盖它们。

## 每条记录的字段

```markdown
## HH:MM — 简短主题

- 会话参与者：用户 / AI 工具
- 目标：
- 用户明确决定：
- AI 执行动作：
- 修改文件：
- 验证：命令、结果、未运行项
- 未完成或阻塞：
- 下一步：
- 数据边界：是否读取或处理敏感内容；如何脱敏
```

只记录可复用事实、决定、行动和结果。不得记录隐藏推理、系统/开发者提示全文、密钥、令牌、Cookie、真实私有代码全文、无关个人数据或未经授权的完整聊天转录。

## “记录所有对话”的可实现边界

仓库规则本身不能读取 Codex、Claude、Cursor 或其他客户端的内部完整聊天记录，也不能保证在客户端崩溃、离线或用户未提供原文时自动恢复每一句消息。因此本项目采用可验证的两层机制：

1. AI 每次会话结束追加结构化摘要，覆盖目标、决定、行动、文件、验证和后续。
2. 如果用户或客户端提供了可保存的原文，可在同一天条目中追加脱敏后的“用户提供原文”；原文必须经过人工确认，不自动把系统提示、秘密或私有代码写入账本。

这能保证每次可观察协作都有记录，但不虚假承诺“自动捕获客户端全部原文”。若需要逐字记录，必须由上层客户端显式导出 transcript，再调用脚本写入私有目录。

## 脚本使用

在仓库根目录运行：

```powershell
pwsh -File .\tools\log-ai-conversation.ps1 -File .\PRIVATE\conversations\2026-09-12.md -Topic "项目初始化规则" -Goal "建立规则与对话账本" -Actions "读取本地规则;创建 AGENTS.md 与兼容入口" -Files "AGENTS.md;CLAUDE.md;GEMINI.md;docs/ai-collaboration.md" -Validation "检查规则文件与 .gitignore" -Next "在下一次会话继续追加"
```

参数值不应包含未脱敏的秘密或完整私有正文。脚本自动创建父目录、写入本地时间和标准字段，并拒绝把目标写到仓库外相对路径。

## 维护规则

如果规则发生变化，先修改 `AGENTS.md`，再同步兼容入口和本文；当天账本记录变更原因。不要从其他项目复制产品事实、私人计划、密钥、完整聊天原文或不适用于 MorphoJudge 的技术约束。
