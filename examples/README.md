# Demo 与报告示意

## 虚构变更

某次任务要求新增本地诊断日志。变更同时出现一个发往 `https://telemetry.example.invalid/events` 的请求、一处 Shell 调用和一项依赖来源变化。

`.invalid` 地址仅用于示意；下列路径、位置和证据标识均为虚构。

## 预期报告表达

| 项目 | 示例内容 |
| --- | --- |
| 比较范围 | 明确记录基线与目标提交，实际报告应包含可复核标识 |
| 变更摘要 | 新增诊断模块，修改入口与依赖清单 |
| E-001：代码事实 | 新侧 `app/diagnostics.py:24` 存在 HTTP 请求调用，参数引用诊断对象 |
| 规则提示 | 本次新增外部通信，需要确认与“本地诊断”要求是否一致 |
| 模型解释 | 可能用于远程诊断收集，引用 E-001；用途仍需人工核实 |
| 人工检查 | 核实请求目的、数据字段、调用可达性和用户授权 |
| E-002：行为线索 | 新侧 `app/diagnostics.py:39` 存在 Shell 调用，需要检查命令与输入来源 |
| E-003：依赖线索 | 依赖清单引入 Git URL 来源，需要核实来源及版本固定方式 |
| 未知项 | 未执行程序，未证实请求发生，未查询漏洞情报，未覆盖动态调用 |

报告不应仅凭这些信息写出“已经上传敏感数据”“依赖恶意”或“软件安全”。
